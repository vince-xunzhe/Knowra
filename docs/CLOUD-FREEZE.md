# 云能力暂时冻结

当前版本专注本机研究。仓库根目录 `cloud-capabilities.json` 的 `enabled: false` 是桌面和后端共用的发布策略；已有环境变量、云地址、浏览器登录态不会重新启用它。日常仍按原方式运行 `./start.sh`，不增加确认或启动参数。

## 当前行为

- 云登录、令牌刷新、同步、续传、签名上传和云端完整推荐暂停。界面显示暂停说明；本地全流程以本地工作完成为准。
- 本地论文、笔记、Wiki、图谱、索骥、识途、Ask、推荐精选和本地 worker 保留。模型 API、Codex CLI、arXiv 等已有能力与费用不属于云同步冻结。
- 后端拒绝同步导出和远端推荐 worker 入口；云模式启动在数据库初始化和调度器启动前被拒绝。`--local` worker 保留。
- 不清除浏览器登录或同步状态，不修改本地数据结构，不迁移、删除、备份或同步研究数据。正常本地研究操作仍按既有逻辑保存数据。
- 云端、同步、Supabase 迁移及移动端源码保留。移动端构建和发布暂停；本次没有发布移动更新，也不会改变已经安装的旧版本。

这次发布不会停止已运行的旧版本服务、已有独立 worker，或改变 Supabase/Fly.io 资源与订阅。已有实例的运维处置需要先确认归属和影响范围；不能凭进程名清理其他任务或研究服务。

## 数据与以后恢复

云端不是完整本机备份。当前上传不包含 PDF 本体、embedding、全部笔记图片及本地研究状态；部分 Wiki 文件上传失败时，其他记录仍可能提交。云端还有独立的收藏、研究焦点、反馈、推荐历史等内容。

同步 commit 将云端论文、节点、边与 Wiki 当作本机完整快照的镜像，会裁剪缺失记录。恢复时不要直接重放旧待续传会话，或使用不完整的本机库执行“最后同步”。

恢复前应在另一个隔离环境中完成：

1. 确认唯一权威本机库，以及云独有数据的保留/合并方案。
2. 验证用户批准的本地一致性备份、云数据库、Auth 用户 ID 映射、Storage 实际文件、RLS/触发器及迁移；数据库导出不包含 Storage 文件本体。
3. 检查账号、地址、对象路径和部署版本。重新登录取得会话，校验逐项内容；旧同步时间不能证明数据一致。
4. 在独立迭代中审查并开启源码策略，验证恢复路径后再部署、分发。不要把本文件当作直接修改生产资源的授权。

备份必须先由用户选择目标并批准复制；见 [开发工作区与验收](DEVELOPMENT.md)。本轮不读取或复制日常研究数据。

## 冻结与停费是两件事

隐藏入口或发布本版本都不会取消订阅。Supabase 按组织订阅，组织里可能有其他项目；Fly.io 的停止机器、磁盘、快照、IP 和附加服务也需要分别核对。后续应先列明 Knowra 专属资源、共享依赖、备份恢复结果和预期账单影响，再决定暂停、降级或释放。不要删除整个组织或影响其他项目。

历史部署/移动文档描述的是恢复后可用的实现，当前冻结期间不要据此部署或构建。源码中保留的云端地址/配置不是启用信号。
