# Ask 正文词回退验收（2026-10-30）

## 问题与边界

合并前四轮后，两句实际问题仍在严格 FTS 查询阶段零命中：

- `世界模型与动作模型的结合，在建模上经历了哪些变化？`
- `世界模型在建模上经历了哪些变化？`

只读排查确认，严格搜索把整段自然语言组合成精确短语；标题、slug、别名回退又找不到只存在于正文中的 `世界模型`、`动作模型`，所以 Codex CLI 没有可读文件，证据门槛正确地拒绝了回答。本修复只补齐这个检索缺口，不降低证据门槛，也不声称提供同义词或语义检索。

排查没有修改或重建用户的 Wiki、论文、数据库、配置或索引，也没有启动、停止或重启用户服务。提交中的回归和测量全部使用临时 Markdown 与 SQLite。

## 修复行为

严格查询仍然优先；严格命中时结果与排序不变。严格零命中且标题／别名也无法提取实体时，搜索才会：

1. 从中文问题中生成有界的 3–8 字候选短语，只保留以 `模型`、`方法`、`算法` 等已知技术后缀结尾的最长有效词组；
2. 用同一 FTS 连接执行计数查询，确认短语确实存在于已索引标题或正文；
3. 丢弃达到 `max(8 篇, 15% 索引文档)` 的常见短语；
4. 最多保留 4 个互不重叠短语，先做 AND，再用 OR 补齐并去重；
5. 在 trace 中分别记录 `body_probe`、实际查询模式、词项与命中数。

正文探测硬上限为 64 次；不生成任意通用 n-gram，避免罕见问句措辞或技术词内部片段变成无关证据。诊断项不被误计为实际 FTS 查询。CLI 仍须成功读取 Wiki 内容才能越过既有证据门槛；无答案问题仍不调用综合模型。

## Definition of Done

- [x] 两句原问题在标题／别名均不含目标词、目标词只存在正文的合成索引中触发正文回退。
- [x] 两词问题先返回同时包含两词的文档，再由 OR 补齐；结果去重。
- [x] 单词问题恢复正文命中。
- [x] 严格标题命中不进入任何回退，原排序路径不变。
- [x] 常见正文短语在 OR 扩展前被拒绝，稀有技术词仍可命中。
- [x] `世界模型` 不会截断为 `界模型` 去误召回 `边界模型`，`动作模型` 也不会通过 `作模型` 误召回 `制作模型`。
- [x] 罕见问句措辞不会作为通用 n-gram 进入证据，API 工具循环可收到正文回退的结构化模式、词项和结果。
- [x] 未知问题的探测次数有硬上限，保持零读取、零引用、零模型调用和 `insufficient` 证据状态。
- [x] Codex CLI 使用真实搜索实现读取至少两份合成 Wiki 内容后才通过跨来源证据门槛；API 既有结构化回退回归继续通过。
- [x] 未新增模型调用、第三方依赖、数据库迁移或 UI 变更。

## 合成测量

命令：

```bash
backend/.venv/bin/python scripts/measure_body_term_fallback.py \
  --output docs/acceptance/ask-body-term-fallback-20261030/measurements.json
```

测量构造 1,075 份临时文档（198 paper／877 concept），其中两句完整问题的严格命中均为 0。结果以仓库中的 [measurements.json](measurements.json) 为准：

| 场景 | 回退结果 | FTS 探测 | 正文探测 p50 |
| --- | --- | ---: | ---: |
| 两个目标词 | `body_and_or`，恢复两个词 | 2 / 64 | 见 JSON |
| 单个目标词 | `body`，恢复一个词 | 1 / 64 | 见 JSON |
| 未知问题 | `strict_no_match` | 0 / 64 | 见 JSON |
| 严格标题命中 | `strict` | 0 / 64 | 不执行正文探测 |

总体耗时还包含既有标题／别名表面扫描，容易受机器抖动影响，因此不以两个独立总体中位数的差值宣称性能提升。`body_probe_only_p50_ms` 隔离记录本次新增工作的成本。

## 已知限制

- 这是精确中文词组回退，不解决同义词、隐含概念、跨语言映射或真正的语义召回。
- 3–8 字候选、技术后缀白名单和 15% 常见词阈值是有界精度保护；它们可能漏掉更长、极短、没有已知后缀，或本身很常见但仍有价值的概念。
- 只有严格查询和标题／别名实体回退都失败时才启用正文探测；本 PR 不重排原有严格命中。
- 问题若同时包含一个已知标题／别名实体和另一个只存在正文的实体，仍沿用既有实体路径，不混入正文探测；这是后续可单独评估的召回边界。
- 找到候选文档不等于问题已有答案。最终回答仍取决于成功读取的内容，并受现有证据门槛约束。
